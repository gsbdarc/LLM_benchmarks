Repairing TV guide dates

What this tests

This demo tests whether an agent can safely repair an LLM’s derived TV guide date. It receives the source dates and the existing derived value, decides whether one date is supported, and records either a correction or an abstention.

Agent decision is the value the agent saved. A human-review flag is a separate warning that someone should inspect the row; an answer can be correct and still carry that warning.

The instructions the agent was given

Every run used exactly these words. The prompt is shown up front because it defines what counts as a repair, an abstention, and a human-review flag.

Summary

Every answer was checked against a known-correct date afterwards. The three kinds of row were chosen deliberately: ones that needed fixing, ones already right (where any change would be damage), and ones where no single date can be correct. Each model gets its own bar in each kind, all on one scale.

The path each model took

Three tools, and the job needs all three in order: read the case, work out the date, record the decision. A wandering agent shows up as extra boxes or a line doubling back.

Rows requiring human review

An abstention is the agent’s decision that no single date is supportable. A human-review flag is separate metadata requesting inspection. This queue also includes wrong answers so silent errors remain visible even when the agent did not set the flag.

What it costs at scale

The original extraction already produced three date fields. Comparing those existing fields can identify candidate rows without another model call; only the candidates are sent to the review agent.
